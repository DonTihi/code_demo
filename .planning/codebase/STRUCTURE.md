## Directory Purposes

**`app/`:**
- Purpose: Core Flask application code
- Contains: Application factory, routes, business logic, templates, static assets
- Key files: `__init__.py` (entry point for app creation), `routes.py` (HTTP handlers), `calculator.py` (math logic)

**`app/templates/`:**
- Purpose: Jinja2 HTML templates
- Contains: Single `index.html` with Jinja2 macros for keypad generation
- Notes: No conditional routing; single template serves both initial page and error/result responses

**`app/static/`:**
- Purpose: CSS and JavaScript assets served directly to browser
- Contains: Stylesheet with light/dark themes, keypad state machine, theme toggle
- Notes: Not minified or bundled; uses IIFE for scope isolation

**`mcp_server/`:**
- Purpose: Expose project context via Model Context Protocol
- Contains: FastMCP server with two tools: `get_project_context()` and `get_demo_request()`
- Notes: Optional; allows Claude to request project info without reading files

**`tests/`:**
- Purpose: Test suite for both Python and JavaScript
- Contains: pytest tests (Python integration & unit tests), Node.js tests (JavaScript logic)
- Key patterns: Fixtures in `conftest.py`, test discovery automatic by pytest

**`tests/js/`:**
- Purpose: Standalone Node.js unit tests for JavaScript modules
- Contains: Tests for `calculator.js` state machine and `theme.js` logic
- Notes: Pytest can run these when Node.js is available; test names follow `*.test.js` pattern

**`.planning/codebase/`:**
- Purpose: Generated codebase documentation
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md (generated by `/gsd-map-codebase`)
- Notes: Committed to git; updated when significant architectural changes occur

**`.claude/`:**
- Purpose: Claude Code configuration and GSD framework files
- Contains: Settings, skills, workflows, hooks
- Notes: Not part of application; used by Claude Code itself

## Key File Locations

**Entry Points:**
- `app/__main__.py`: Script entry for `python -m app` (runs Flask dev server)
- `app/__init__.py:create_app()`: Application factory imported by `__main__.py` and test fixtures
- `mcp_server/server.py`: MCP server entry (spawned by Claude Code's MCP client)

**Configuration:**
- `pyproject.toml`: pytest configuration (test paths, coverage settings, coverage fail-under target of 100%)
- `.mcp.json`: MCP server configuration (command to run `mcp_server/server.py`)
- `requirements.txt`: Python package dependencies
- `CLAUDE.md`: Project-specific engineering rules and demo request

**Core Logic:**
- `app/calculator.py`: Pure functions for arithmetic operations and input validation
- `app/routes.py`: HTTP request handlers (GET /, POST /calculate)
- `app/templates/index.html`: Single HTML template with all UI markup and Jinja2 logic

**UI & Interaction:**
- `app/static/calculator.js`: Client-side keypad state machine, handles chaining, form submission
- `app/static/theme.js`: Dark/light mode toggle, localStorage persistence, no-flash initialization
- `app/static/style.css`: All styling; CSS custom properties for theme colors

**Tests:**
- `tests/conftest.py`: Shared pytest fixtures (`app`, `client`)
- `tests/test_calculator.py`: Unit tests for parsing and operations (44 lines, ~18 test cases)
- `tests/test_app.py`: Integration tests for Flask routes and templates (209 lines, ~25 test cases)
- `tests/test_entrypoint.py`: Tests for `__main__.py`
- `tests/test_mcp_server.py`: Tests for MCP server tools
- `tests/test_keypad_js.py`: Pytest wrapper to run Node.js tests
- `tests/js/calculator.test.js`: Node.js tests for state machine logic
- `tests/js/theme.test.js`: Node.js tests for theme detection and persistence

## Naming Conventions

**Files:**
- **Python modules:** lowercase with underscores (`calculator.py`, `conftest.py`, `__init__.py`)
- **JavaScript files:** lowercase with hyphens for utilities, `.test.js` suffix for tests (`calculator.js`, `theme.js`, `calculator.test.js`)
- **Templates:** lowercase (`index.html`)
- **Stylesheets:** lowercase (`style.css`)
- **Test files:** `test_*.py` for pytest discovery, `*.test.js` for Node.js discovery

**Directories:**
- **Application code:** lowercase (`app`, `mcp_server`)
- **Test code:** `tests` (pytest convention)
- **Static assets:** `static` (Flask convention)
- **Templates:** `templates` (Flask convention)
- **Test subdirectories:** `js` for JavaScript-specific tests

**Python:**
- **Functions:** lowercase with underscores (`parse_number`, `create_app`, `divide`)
- **Classes:** PascalCase (none in this demo)
- **Constants:** UPPERCASE (`OPERATIONS`, `EMPTY_STATE`)
- **Private functions:** prefixed with `_` (e.g., `_render()` in routes.py)

**JavaScript:**
- **Functions:** camelCase (`applyKey`, `pressOperator`, `toggleTheme`, `isDigit`)
- **Constants:** UPPERCASE (`MAX_LENGTH`, `OPERATIONS`, `THEME_KEY`)
- **HTML attributes:** kebab-case (`data-calculator`, `data-key`, `data-operator`)

**HTML:**
- **Class names:** kebab-case (`.display-line`, `.key-operator`, `.legacy-controls`)
- **IDs:** kebab-case (`#theme-toggle`)
- **Data attributes:** kebab-case (`data-expression`, `data-operator-symbols`, `data-division-by-zero-message`)

## Where to Add New Code

**New Feature (UI change):**
- **HTML markup:** `app/templates/index.html` (Jinja2 macros for reusable elements)
- **Styling:** `app/static/style.css` (use CSS custom properties for themeable values)
- **Client interaction:** `app/static/calculator.js` (add to state machine or event handlers)
- **Tests:** `tests/test_app.py` (integration test for page rendering)

**New Feature (calculator logic):**
- **Operation function:** `app/calculator.py` (add function, register in `OPERATIONS` dict)
- **Input validation:** `app/calculator.py` (extend `parse_number()` if needed)
- **Route handler:** `app/routes.py` (modify `/calculate` POST handler if parameters change)
- **Tests:** `tests/test_calculator.py` (unit tests for new operation)

**New Route:**
- **Handler:** `app/routes.py` (add new function decorated with `@bp.get()` or `@bp.post()`)
- **Template:** `app/templates/` (create new template file if needed, or reuse `_render()`)
- **Tests:** `tests/test_app.py` (integration tests for the route)

**New Theme Color Variable:**
- **Stylesheet:** `app/static/style.css` (add `--color-name` to both light (`:root`) and dark (`[data-theme="dark"]`) sections)
- **Usage:** Reference via `var(--color-name)` in selectors
- **Tests:** `tests/test_app.py:test_calculate_button_is_red` shows how to assert CSS values exist

**New Utility Function:**
- **Shared logic:** `app/calculator.py` (if math-related) or new module in `app/` (if app-specific)
- **Client utility:** `app/static/calculator.js` inside the IIFE (not exported to global scope)
- **Tests:** Corresponding test file (`tests/test_calculator.py` for server, `tests/js/calculator.test.js` for client)

## Special Directories

**`__pycache__/`:**
- Purpose: Python bytecode cache
- Generated: Yes (automatically by Python interpreter)
- Committed: No (in `.gitignore`)

**`.pytest_cache/`:**
- Purpose: pytest internal caching
- Generated: Yes (automatically by pytest)
- Committed: No (in `.gitignore`)

**`.venv/`:**
- Purpose: Python virtual environment
- Generated: Yes (by `python -m venv .venv`)
- Committed: No (in `.gitignore`)

**`.coverage`:**
- Purpose: Coverage data file
- Generated: Yes (by pytest --cov)
- Committed: No (in `.gitignore`)

**`.git/`:**
- Purpose: Git repository metadata
- Generated: Yes (by `git init`)
- Committed: No
